Simulation Structure

This section explains how the simulation is structured, covering key components such as the inverse kinematics of a simple Bill-E robot, all the way up to a multi-robot autonomous structure assembly. To fully understand the different parts of the simulation, we will progress from an empty Three.js scene to a fully autonomous simulation.

🔍 Simulation Workflow: From High to Low Level

  • Input: `.stl` file representing the 3D structure to be built.

    Output:

    • A voxelized representation listing all required voxel positions.
    • (Optional) A preview of the structure in Three.js.

  • Input: List of voxel positions & number of robots.

    Output:

    • Optimized starting positions for each robot.
    • A structured sequence defining voxel placement order.

  • Input: List of sub-goals to construct the structure.

    Output: A sequence of actions required to achieve all sub-goals efficiently.

  • Input: List of actions for sub-goals.

    Output:

    • Start and goal positions (plus orientation) for each leg of every robot.

  • Input: Start & goal positions with leg orientations.

    Output: Computed joint angles for executing the movement.

Code Structure

The simulation was entirely built in JavaScript, leveraging Three.js to enable visualization on any device without requiring installation—only an internet connection is needed :)

The global structure of the code is as follows:

            Demo Code/
            ├── demo/                   <-- Contains different interactive HTML demos for various simulation aspects.
            ├── js/                     <-- Core JavaScript scripts handling the simulation logic
            │   ├── GUI/                <-- Folder with GUI file (one per demo)
            │   ├── d.js                <-- Additional helper functions
            │   ├── robot.js            <-- Core robot structure & logic
            │   ├── robot_movement.js   <-- Movement planning & execution
            │   ├── scene.js            <-- Three.js scene setup & rendering
            ├── lib/                    <-- External libraries (Three.js, dat.GUI, etc.)

Creating the Robot

The robot used in this simulation is based on the Bill-E robot, initially introduced in this research paper: 📄 Material Robots: Modular Digital Assembly .

Newer versions of Bill-E may vary in size, but they all function the same way. Bill-E is a 5 DOF (Degrees of Freedom) robotic arm with five joints:

  • Joints 0 & 4: Rotate around the normal axis to the surface.
  • Joints 1, 2, & 3: Rotate around a local perpendicular axis (which depends on the robot’s orientation).

Each joint has a rotation range from -135° to 135°, giving it a 270° total range. This range is designed to ensure the cable-driven actuation of the robot remains functional without excessive strain. It is important to note that each angle is defined relative to the previous one as showd here:

Voxel Importation

The Bill-E robot is designed to operate in a voxelized environment. In the latest version, each structural unit consists of 4 voxels assembled together. This modification was made to prevent beam flexure in thinner structures.

This differs from Amira's original simulation, which used a simpler voxel-based approach.

New Voxel Stacking Rule:

  • In reality, the voxels are physically connected using screws, which the robot rotates to fix or unfix them.
  • Each voxel is only directly attached to the voxel below it, meaning that for a stable and fully connected structure, each voxel must rest on at least two others.
  • This constraint prevents the creation of perfectly cubic structures as the stacking method requires a staggered placement.

To address this limitation, we are working on implementing an additional 3x2 voxel type that will allow for more versatile and compact structures.
