Bill-E Robot Simulation

📌 Technical Implementation

This section details the core implementation of the Bill-E robot in the simulation. The robot's behavior is implemented using object-oriented programming through a dedicated THREERobot class.

  • 🔹 Robot Class in robot.js

    The robot is implemented as a class in robot.js. This class defines the robot’s properties and its essential functionalities. The constructorinitializes the robot by setting:

    • ✅ The position and orientation of both legs.
    • ✅ The joint limits (range of motion).
    • ✅ The robot geometry (size of each leg segment).

    This allows creating multiple instances of the robot with different parameters.

  • 🔹 Core Functions in robot.js

    Some key methods implemented in robot.jsinclude:

    • 🚀 setToTarget(position, normal): Moves the robot to the target position and adjusts the leg orientation automatically.
    • ⚙️ updateAnglesFromTarget(): Computes the necessary joint angles to reach the desired position.
    • 🔄 swapFixedLeg(): Changes the leg that remains fixed while the other moves.
    • 🔧 reinitializeRobot(): Destroys the current instance and re-initializes a new robot with updated parameters.

  • 🔹 Robot Movement & Inverse Kinematics

    The movement of the robot is handled by inverse kinematics, which calculates the joint angles needed to reach a given position. The updateAnglesFromTarget() function automatically adjusts the angles based on the robot's position.

    Additionally, movements are smoothed using Bezier interpolation, ensuring realistic transitions between different poses.

  • 🔹 Integration with Three.js

    The robot’s 3D model is visualized using **Three.js**, where each joint is represented as a rotatable object. Scene management, rendering, and user interactions are handled dynamically through Three.js functions.

🔹 Inverse Kinematics (IK)

The goal of the inverse kinematics system is to compute the joint angles required for the robot’s end effector to reach a target position. Since Bill-E is a 5 Degrees of Freedom (DOF) robotic arm, solving IK is split into two main steps.

✔ Step 1: Computing Joint 0 (Yaw Rotation)

The first step in IK is calculating \(\theta_0\) (joint 0), which determines how the robot rotates around its base. To achieve this, the target position is first projected onto the plane defined by the origin’s normal.

The projected target position is computed as:

\[ \mathbf{target}_{\text{proj}} = \mathbf{target} - (\mathbf{normal} \cdot (\mathbf{target} - \mathbf{origin})) \cdot \mathbf{normal} \]

Then, we compute \(\theta_0\) using the dot and cross product between the robot’s **movement direction** and **projected target vector**:

\[ \theta_0 = \text{atan2} \left( (\mathbf{direction} \times \mathbf{target}_{\text{proj}}) \cdot \mathbf{normal}, \mathbf{direction} \cdot \mathbf{target}_{\text{proj}} \right) \]

✔ Step 2: Solving 3-DOF Inverse Kinematics

Once \(\theta_0\) is determined, we solve the remaining three angles (\(\theta_1, \theta_2, \theta_3\)) using classic inverse kinematics for a 3-DOF robotic arm.

First, we compute the effective distance \( d \) from the base to the projected target:

\[ d^2 = x^2 + y^2 \]

Using the **law of cosines**, we find \(\theta_2\):

\[ \cos(\theta_2) = \frac{d^2 - L_1^2 - L_2^2}{2 L_1 L_2} \] \[ \theta_2 = \cos^{-1} (\cos(\theta_2)) \]

Then, we compute \(\theta_1\) using:

\[ \theta_1 = \tan^{-1} \left( \frac{y}{x} \right) - \tan^{-1} \left( \frac{L_2 \sin(\theta_2)}{L_1 + L_2 \cos(\theta_2)} \right) \]

Finally, \(\theta_3\) is calculated as:

\[ \theta_3 = \psi - (\theta_1 + \theta_2) \]

The system also includes a constraint on \(\theta_3\) to ensure stability during movement.

🔹 Fixed Leg Swapping

While IK allows the robot to reach new positions, **Fixed Leg Swapping** enables it to actually move. This process involves shifting the fixed leg to the opposite one and reconstructing the robot at its new base.

✔ Initial Attempt: Directly Swapping Legs

The first approach involved swapping the first and last elements of the **Three.js THREERobot** hierarchy. However, this method led to inconsistencies when the two legs were positioned on different planes (i.e., different normal vectors).

✔ Final Working Approach: Reconstructing Around the Moving Leg

The final and correct solution was to:

  • ✅ Rebuild the robot at the new moving leg’s position instead of swapping hierarchy elements.
  • ✅ Update the robot’s direction and orientation to match the new plane.
  • ✅ Recompute the inverse kinematics immediately after swapping to ensure a smooth transition.

This is implemented in the function reinitializeRobot(), which reconstructs the robot while preserving its internal state.
